Chapter 07 Security Lab

SQL Injection & PreparedStatement AST Defense Lab

See why String concatenation in java.sql.Statement corrupts the database Abstract Syntax Tree (AST), and how PreparedStatement parameter binding creates an impenetrable binary isolation boundary.

💡 First Principles Explanation:

A database query optimizer compiles SQL queries into an Abstract Syntax Tree (AST). When using Statement, user strings are parsed directly by the SQL parser, turning untrusted input into executable boolean logic (e.g. OR '1'='1').

With PreparedStatement, the AST structure is compiled first. User parameters are sent over the Type 4 network socket driver as isolated literal values, never touching the SQL syntax grammar!

CHAPTER 07 ARCHITECTURAL INSIGHTS:
• Type 4 Pure Java Driver: Directly translates JDBC calls into vendor network socket packets (e.g. MySQL port 3306).
• ResultSet 1-Based Indexing: Cursor points *before* first row initially; advance via rs.next() before reading columns.
• ACID Transactions: Call conn.setAutoCommit(false), execute updates, then conn.commit() or conn.rollback() on failure.
• HikariCP Pooling: Avoids expensive TCP 3-way handshakes and SSL negotiation on every request by leasing pre-warmed sockets.
