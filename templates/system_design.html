CH 01 DISTRIBUTED ARCHITECTURE BLUEPRINT

Design a URL Shortener (TinyURL / Bitly)

Executive Summary:

A URL shortener is a classic read-heavy distributed service designed to convert arbitrary long URLs into compact 7-character aliases (e.g. https://tiny.notes/b9X7qL). The service operates under high availability (99.99%), sub-20 millisecond redirect SLA, and handles asymmetric traffic (100:1 read-to-write ratio) using multi-tier Redis caching, Base62 encoding, and a dedicated Key Generation Service (KGS).

Key Engineering Takeaways:
  • Base62 Encoding vs Hash Truncation: 62 alphanumeric characters ([0-9a-zA-Z]) raised to length 7 provides 62^7 ≈ 3.52 Trillion unique short URLs. Truncating MD5 hashes causes severe collision rates, whereas converting unique 64-bit integer IDs or fetching from KGS has 0% collision probability.
  • HTTP 301 vs 302 Redirect Semantics: HTTP 301 (Moved Permanently) instructs the browser to cache the target URL locally, eliminating subsequent server round-trips but breaking real-time click telemetry. HTTP 302 (Found) forces the browser to consult the backend on every click, enabling analytics tracking at the expense of higher QPS.
  • 80-20 Pareto In-Memory Caching: With a 100:1 read ratio, caching 20% of daily hot links in an in-memory Redis cluster absorbs 80% of read volume, keeping relational/NoSQL database queries to a minimum.
  • Database Sharding & Hot Spot Prevention: Using Hash(short_code) % N (Consistent Hashing) spreads URL rows uniformly across shards, avoiding hot partitions created by user-based or range-based sharding.
INTERVIEW ARCHITECTURAL CHECKLIST:
1. Step 1: Clarify Scope
Traffic volume, read/write ratio, custom aliases, link expiration.
2. Step 2: Capacity Estimation
Calculate Write QPS, Read QPS, 5-year storage, and Redis RAM.
3. Step 3: API Design
POST /api/v1/urls and GET /{short_code}.
4. Step 4: Data Model
SQL schema, unique B-tree index on short_code.
5. Step 5: High-Level Design
LB → App Servers → Redis Cache → Sharded DB.
6. Step 6: Deep Dives
KGS ZooKeeper coordination, 301 vs 302, Kafka analytics stream.
